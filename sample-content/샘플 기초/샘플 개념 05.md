# 샘플 개념 05

## 기초질문

> 샘플 개념 05가 실패하면 어떻게 복구하나요?

## 평가 체크리스트

- [ ] **실패 감지**: 실패를 어떻게 알아차리는지 말할 수 있는가?
  - 알아야 할 내용: 정해 둔 시간 안에 응답이 없거나 결과 검증에 실패하면 실패로 봅니다.
  - 빠뜨리면: 샘플 개념 05가 실패했다는 것은 어떻게 아나요?
- [ ] **복구 순서**: 실패한 뒤 복구하는 순서를 말할 수 있는가?
  - 알아야 할 내용: 마지막으로 성공한 상태로 되돌린 뒤 같은 작업을 다시 시도합니다.
  - 빠뜨리면: 실패한 뒤에는 어떤 순서로 복구하나요?

## 1질문 3답변

### 답변 A: 원리형

> 마지막으로 성공한 상태를 남겨 두었다가 실패하면 그 상태로 되돌립니다.

- 키워드: 성공한 상태
- 꼬리 질문: 말씀하신 성공한 상태를 조금 더 여쭤보겠습니다. 실패는 언제 판정하나요? -> **실패 감지**
- 놓친 항목: **실패 감지**

### 답변 B: 실무형

> 업로드가 중간에 끊겨서 처음부터 다시 보내도록 바꾼 적이 있습니다.

- 키워드: 끊긴 업로드
- 꼬리 질문: 말씀하신 끊긴 업로드를 조금 더 여쭤보겠습니다. 끊긴 것은 어떻게 알았나요? -> **실패 감지**
- 놓친 항목: **실패 감지**, **복구 순서**(재시도만 말함)

### 답변 C: 직관형

> 게임에서 세이브 지점으로 돌아가는 것과 같습니다.

- 키워드: 세이브 지점
- 꼬리 질문: 말씀하신 세이브 지점을 조금 더 여쭤보겠습니다. 세이브는 언제 하나요? -> **복구 순서**
- 놓친 항목: **실패 감지**, **복구 순서**

## 꼬리 질문

### 같은 실패가 반복되면 어떻게 하나요?

정해 둔 횟수만큼만 다시 시도하고, 그 뒤에는 실패를 기록하고 사람에게 알립니다.
