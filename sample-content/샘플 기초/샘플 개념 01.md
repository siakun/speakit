# 샘플 개념 01

## 기초질문

> 샘플 개념 01은 무엇이고 언제 필요한가요?

다른 표현
- 샘플 개념 01을 처음 듣는 사람에게 설명해 주세요.

## 평가 체크리스트

- [ ] **한 문장 정의**: 샘플 개념 01이 무엇인지 한 문장으로 말할 수 있는가?
  - 알아야 할 내용: 샘플 개념 01은 앱의 화면과 노트 형식을 보여 주려고 지어낸 가상의 개념입니다.
  - 빠뜨리면: 샘플 개념 01을 한 문장으로 정의해 주시겠어요?
- [ ] **필요한 상황**: 샘플 개념 01이 필요한 상황을 예로 들 수 있는가?
  - 알아야 할 내용: 상태를 한곳에서 관리해야 할 때 필요하다고 설명합니다.
  - 빠뜨리면: 샘플 개념 01은 어떤 상황에서 필요한가요?
- [ ] **동작 순서**: 샘플 개념 01이 동작하는 순서를 단계별로 말할 수 있는가?
  - 알아야 할 내용: 입력을 받고, 상태를 바꾸고, 결과를 돌려주는 세 단계로 설명합니다.
  - 빠뜨리면: 샘플 개념 01은 어떤 순서로 동작하나요?
- [ ] **치르는 비용**: 샘플 개념 01을 쓸 때 대가로 치르는 것을 말할 수 있는가?
  - 알아야 할 내용: 상태를 보관하는 메모리와 상태를 맞추는 코드가 늘어납니다.
  - 빠뜨리면: 샘플 개념 01을 쓰면 무엇을 대가로 치르나요?
- [ ] **대안**: 샘플 개념 01 대신 쓸 방법과 고르는 기준을 말할 수 있는가?
  - 알아야 할 내용: 상태가 짧게 살면 함수 인자로 넘기는 방법이 더 단순합니다.
  - 빠뜨리면: 샘플 개념 01 대신 무엇을 쓸 수 있고, 언제 그쪽이 낫나요?

## 1질문 3답변

### 답변 A: 원리형

> 샘플 개념 01은 입력을 받아 상태를 바꾸고 결과를 돌려주는 개념입니다. 세 단계가 순서대로 일어나야 결과가 맞습니다.

- 키워드: 상태, 순서
- 꼬리 질문: 말씀하신 순서를 조금 더 여쭤보겠습니다. 순서가 바뀌면 무엇이 깨지나요? -> **동작 순서**
- 놓친 항목: **필요한 상황**, **치르는 비용**, **대안**

### 답변 B: 실무형

> 화면 상태를 저장할 때 샘플 개념 01을 썼습니다. 저장 시점을 한곳으로 모으니 같은 버그가 다시 나지 않았습니다.

- 키워드: 저장 시점
- 꼬리 질문: 말씀하신 저장 시점을 조금 더 여쭤보겠습니다. 한곳으로 모으면 무엇을 잃나요? -> **치르는 비용**
- 놓친 항목: **한 문장 정의**, **동작 순서**(저장 단계만 말함), **대안**

### 답변 C: 직관형

> 샘플 개념 01은 메모장에 적어 두고 필요할 때 꺼내 보는 것과 비슷합니다.

- 키워드: 메모장
- 꼬리 질문: 말씀하신 메모장 비유를 조금 더 여쭤보겠습니다. 비유와 실제 동작은 어디서 다른가요? -> **한 문장 정의**
- 놓친 항목: **동작 순서**, **치르는 비용**, **대안**

## 답변

<!-- 정의 -> 상황 -> 순서 -> 비용 -> 대안 -->
샘플 개념 01은 입력을 받아 상태를 바꾸고 결과를 돌려주는 개념입니다. 상태를 한곳에서 관리해야 할 때 필요합니다. <u>입력, 상태 변경, 결과 반환</u>의 순서로 동작합니다. 대신 상태를 보관하는 메모리가 듭니다. 상태가 짧게 살면 함수 인자로 넘기는 편이 더 단순합니다.

## 꼬리 질문

### 샘플 개념 01을 쓰지 않으면 어떤 문제가 생기나요?

상태를 여러 곳에서 바꾸게 되어 어느 쪽이 최신인지 알기 어렵습니다.

### 샘플 개념 01의 상태는 언제 지우나요?

결과를 돌려준 뒤 그 상태를 더 읽는 곳이 없을 때 지웁니다.
