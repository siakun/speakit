# 샘플 비교 03

## 기초질문

> 샘플 비교 03에서 두 방식을 한 화면에 함께 쓰다가 같은 값이 서로 다르게 보이는 문제가 생겼다면, 원인을 어디서부터 찾고 어떤 기준으로 한쪽 방식으로 통일할지 순서대로 설명해 주세요.

## 평가 체크리스트

- [ ] **원인 추적**: 값이 갈라진 지점을 찾는 순서를 말할 수 있는가?
  - 알아야 할 내용: 값을 바꾸는 모든 경로를 나열하고, 두 화면이 같은 값을 읽는지부터 확인합니다.
  - 빠뜨리면: 어디서부터 원인을 찾나요?
- [ ] **통일 기준**: 한쪽 방식으로 통일하는 기준을 말할 수 있는가?
  - 알아야 할 내용: 값을 바꾸는 곳이 여러 곳이면 함께 쓰는 저장소 쪽으로 통일합니다.
  - 빠뜨리면: 어느 쪽으로 통일할지는 무엇을 보고 정하나요?

## 1질문 3답변

### 답변 A: 원리형

> 값을 바꾸는 경로를 모두 찾은 뒤, 바꾸는 곳이 여럿이면 한 저장소로 모읍니다.

- 키워드: 바꾸는 경로
- 꼬리 질문: 말씀하신 바꾸는 경로를 조금 더 여쭤보겠습니다. 경로는 어떻게 찾나요? -> **원인 추적**
- 놓친 항목: **원인 추적**(순서를 말하지 않음)

### 답변 B: 실무형

> 장바구니 수량이 두 화면에서 다르게 보여서 수량을 한 저장소에서만 바꾸도록 고쳤습니다.

- 키워드: 장바구니 수량
- 꼬리 질문: 말씀하신 장바구니 수량을 조금 더 여쭤보겠습니다. 갈라진 지점은 어떻게 찾았나요? -> **원인 추적**
- 놓친 항목: **원인 추적**, **통일 기준**(결과만 말함)

### 답변 C: 직관형

> 두 사람이 각자 메모한 약속 시간이 다른 것과 같아서 달력 하나에만 적게 합니다.

- 키워드: 달력 하나
- 꼬리 질문: 말씀하신 달력 하나를 조금 더 여쭤보겠습니다. 어느 메모가 틀렸는지는 어떻게 아나요? -> **원인 추적**
- 놓친 항목: **원인 추적**

## 꼬리 질문

### 통일한 뒤 같은 문제가 다시 생기지 않게 하려면 어떻게 하나요?

값을 바꾸는 함수를 하나만 두고, 두 화면이 같은 값을 보여 주는지 확인하는 검사를 추가합니다.
