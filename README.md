# speakit

<!-- INTENT: 알고 있는 개념을 면접관에게 정돈된 문장으로 말하는 연습에 집중한다. 문제 목록이나 성취 지표를 첫 화면에 늘어놓지 않고 질문 한 장, 직접 한 자기 점검, 이어지는 꼬리 질문을 중심에 둔다. -->
CS 질문을 보고 소리 내어 설명한 뒤, 카드를 뒤집어 평가 기준과 대조하는 모바일 웹앱입니다. 질문, 평가 기준, 서로 다른 답변과 꼬리 질문을 담은 질문 파일(JSON)을 불러와 카드로 연습합니다. 앱 화면에는 `기초질문`이라는 이름으로 표시합니다.

사이트는 https://siakun.github.io/speakit/ 에서 엽니다. 사이트에는 앱과 가짜 샘플 덱만 있고, 실제 질문은 들어 있지 않습니다.

## 질문 파일과 공유 링크

<!-- INTENT: 면접 질문과 답변은 공개 사이트와 저장소에 두지 않는다. 서버나 저장소를 거치지 않고 다른 기기로 옮기는 수단으로 주소의 조각(# 뒤)을 사용한다. 조각은 브라우저가 서버로 보내지 않는다. -->
시작 화면에서 질문 파일을 고르면, 앱이 파일 형식을 검사한 뒤 내용을 압축해 주소의 `#deck=` 뒤에 담습니다. 이 주소를 그대로 복사해 다른 기기에서 열면 같은 질문으로 연습합니다. 오른쪽 위의 분야 선택에 있는 `공유 링크 복사`는 현재 주소 전체를 복사합니다.

- 주소의 `#` 뒤는 브라우저가 서버로 보내지 않으므로, 질문은 GitHub Pages를 거치지 않습니다.
- 대신 링크를 가진 사람은 누구나 질문 전체를 볼 수 있습니다. 메신저로 보낸 링크는 대화 기록에, 연 주소는 브라우저 방문 기록과 동기화 계정에도 남습니다.
- 불러온 덱은 이 브라우저에도 저장되므로 `#` 없이 사이트를 열어도 이어서 연습합니다. 분야 선택의 `이 기기에서 지우기`는 덱과 연습 기록을 함께 지웁니다.

링크는 질문이 많을수록 길어집니다. 실제 길이는 [질문 파일 만들기](#질문-파일-만들기)의 변환 스크립트가 미리 계산해 보여 주고, 앱도 링크를 복사할 때 알려 줍니다. Chrome은 2MB(2,097,152자)를 넘는 주소를 열지 않습니다. 메신저와 메모 앱은 긴 메시지를 자르거나 링크로 인식하지 못할 수 있으므로, 실제로 사용할 경로로 한 번 보내 열어 봅니다. 잘린 링크는 덱을 열지 않고 오류를 알립니다. 링크로 옮기기 어려우면 JSON 파일을 그 기기로 옮겨 직접 불러옵니다.

## 질문 파일 만들기

질문 파일은 아래 필드를 담은 JSON입니다. 형식 검사는 `src/deckFile.ts`의 `parseDeck`이 정하며, 필수가 아닌 값은 빼도 됩니다. 문자열에는 마크다운을 사용할 수 있습니다.

| 필드 | 내용 |
|---|---|
| `format`, `version` | `"speakit-deck"`, `1`. 필수 |
| `title` | 덱 이름. 분야 선택에 표시 |
| `topics[]` | 질문 카드 목록. 1개 이상 필수 |
| `topics[].id` | 책갈피와 체크 기록의 키. 덱 안에서 겹치지 않아야 하며, 빼면 `분야/제목` |
| `topics[].category`, `title`, `question` | 분야, 제목, 카드 앞면의 질문. 필수 |
| `topics[].checklist[]` | `label`(항목 이름), `criterion`(기준), `detail`(알아야 할 내용), `followup`(빠뜨렸을 때의 꼬리 질문). 모두 필수이며 한 질문 안에서 `label`이 겹치지 않아야 함 |
| `topics[].examples[]` | `title`, `answer`, `metadata`. 비교 답변의 제목, 답변, 메모 |
| `topics[].followups[]` | `question`, `answer`. 꼬리 질문과 답변이며, 답변이 비면 아직 없다고 표시 |
| `topics[].answerDraft`, `references` | 작성 중인 답변 노트, 참고자료 |

마크다운 질문 노트에서 만들 때는 변환 스크립트를 사용합니다. 노트 폴더의 하위 폴더 하나가 분야 하나이고, 그 안의 마크다운 파일 하나가 질문 하나입니다. 폴더 바로 아래에 있는 파일은 읽지 않습니다. 출력 경로를 빼면 파일을 저장하지 않고 형식 검사 결과, 질문 수와 링크 길이만 보여 줍니다.

```powershell
npm run deck:export -- <질문 노트 폴더> <질문 파일.json>
```

변환 스크립트는 노트 파일에서 아래 표의 `##` 절만 읽고, 표에 없는 절과 `<!-- -->` 주석은 질문 파일에 넣지 않습니다. 형식의 예는 `sample-content`에 있습니다.

| 절 | 질문 파일의 필드 |
|---|---|
| `기초질문` | 첫 인용문(`>`)이 `question`. 없으면 변환 오류 |
| `평가 체크리스트` | `- [ ] **항목 이름**: 기준` 항목과 그 아래의 `- 알아야 할 내용:`, `- 빠뜨리면:`이 `checklist`. 하위 항목이 빠지면 변환 오류 |
| `1질문 3답변` | `###` 제목마다 인용문은 `answer`, 그 아래 목록은 `metadata` |
| `꼬리 질문` | `###` 제목이 `question`, 본문이 `answer` |
| `답변` | `answerDraft` |
| `참고자료` | `references` |

## 실행

저장소 루트에서 실행합니다. Node.js 요구 버전은 `package.json`의 `engines`를 따릅니다.

```powershell
npm install
npm run dev
```

개발 서버는 시작 화면부터 엽니다. 주소 끝에 `#sample`을 붙이면 샘플 덱으로 바로 시작합니다.

터미널에 표시된 Local 주소를 PC에서 엽니다. iPhone에서는 같은 Wi-Fi에 연결한 뒤 Network 주소를 Safari에서 엽니다. Windows 방화벽이 연결을 막으면 개인 네트워크의 Node.js 연결 허용 상태를 확인합니다. 외부 공개나 터널 연결은 실행 명령에 포함하지 않습니다.

배포용 정적 파일은 `npm run build`로 만들고 `npm run preview`로 확인합니다. 빌드에는 샘플 덱만 들어갑니다. 자산 경로가 상대 경로라서 `dist`는 도메인 루트와 하위 경로 어느 쪽에 올려도 동작합니다.

실기기의 애니메이션 성능은 배포용 미리보기에서 확인합니다. 주소 끝에 `?fps=1`을 붙이면 JavaScript의 `requestAnimationFrame` 호출 주기를 표시합니다. `p95`는 측정한 간격 중 95%가 그 값 이하라는 뜻입니다. 기본 스크롤은 이 콜백과 독립적으로 처리되므로, 표시된 수치를 가로 또는 세로 스크롤의 실제 fps로 해석하지 않습니다. 짧은 표본은 수치 대신 측정 구간 부족으로 표시합니다. 매개변수를 지우면 진단 코드도 불러오지 않습니다.

## 사용

질문 카드를 탭하면 답변 기준이 나타납니다. 말했던 항목을 체크하고 빠뜨린 내용의 꼬리 질문을 눌러 이어서 연습합니다. 카드 상단의 질문을 탭하면 다시 앞면으로 돌아갑니다.

좌우 스와이프와 하단 화살표로 질문을 넘깁니다. 한 회차 안에서는 질문이 중복되지 않으며, 마지막 질문 뒤에서 다시 섞어 시작합니다. 오른쪽 위의 분야 선택에서 질문을 검색하거나 분야를 바꿉니다. 책갈피로 저장한 질문은 같은 메뉴의 `다시 볼 질문`에서 모아 봅니다.

답변 기준은 질문 파일의 평가 항목입니다. `1질문 3답변`은 모범 답안이 아니라 키워드에 따라 꼬리 질문이 달라지는 모습을 보여 주는 비교 자료입니다. 오류, 빠뜨린 항목과 가상의 경험담이라는 구분을 유지합니다. 작성 중인 답변 노트도 완성을 보장하지 않으므로 초안으로 표시합니다. 꼬리 질문에 답이 없으면 그 상태를 그대로 알립니다.

불러온 덱, 책갈피, 체크한 항목, 분야와 질문 위치는 같은 브라우저의 localStorage에 저장합니다. 브라우저 데이터를 삭제하면 기록도 사라집니다. 체크는 자기 점검이며 자동 채점이 아닙니다. 녹음, STT, AI 피드백은 아직 구현하지 않았습니다.

## 배포

`main`에 push하면 `.github/workflows/deploy.yml`이 검사와 빌드를 거쳐 GitHub Pages에 배포합니다. 빌드에 실제 질문이 없으므로 다른 저장소를 읽지 않고 자격증명도 필요 없습니다. 질문을 고쳤을 때는 사이트를 다시 배포하지 않고, 질문 파일을 다시 만들어 불러옵니다.

## 원본과 구현 경계

마크다운 노트를 읽는 규칙은 `scripts/content.mjs`, 질문 파일의 형식 검사와 링크 인코딩은 `src/deckFile.ts`에 있습니다. 변환 스크립트, 앱, 검사가 같은 두 파일을 사용하므로 변환을 통과한 파일은 앱에서도 열립니다. 노트에서 만든 질문 파일은 사본이므로 직접 고치지 않고, 노트를 고친 뒤 다시 만듭니다.

화면은 React와 TypeScript, 개발과 정적 빌드는 Vite를 사용합니다. 콘텐츠 타입과 학습 기록 타입을 분리해, 향후 녹음과 전사 결과를 추가해도 질문 원본이나 직접 체크한 기록을 자동 평가 결과로 덮어쓰지 않도록 합니다. 음성 파일과 비동기 평가를 붙일 때는 별도의 시도 기록, 저장 정책과 서버 인증을 설계합니다.

카드는 브라우저 기본 가로 스크롤과 CSS Scroll Snap으로 이동합니다. 손가락 추종, 관성과 카드 정렬은 브라우저가 처리하며 JavaScript로 매 프레임 위치를 바꾸지 않습니다. 이웃 카드가 함께 움직이고, 한 번의 스와이프가 다음 카드의 정렬 지점을 지나치지 않도록 설정합니다. 이동 중에도 다시 잡아 방향을 바꿀 수 있으며 하단 버튼은 같은 영역에 기본 부드러운 스크롤을 요청합니다. PC에서는 하단 버튼이나 가로 휠과 트랙패드로 이동합니다. 답변이 펼쳐진 카드는 화면을 벗어날 때까지 내용을 유지합니다. 선택과 정착의 동기화는 `src/CardCarousel.tsx`에서 관리합니다.

다른 앱에 같은 구조를 적용할 때는 [iPhone 웹앱의 120fps 스크롤 구현 가이드](docs/ios-native-scroll-snap.md)를 참고합니다. 최소 예제, 카드 상태 설계와 실제 표시 프레임을 구분하는 검증 절차를 제공합니다.

화면 밖의 카드도 이동 거리를 계산할 슬롯은 유지하지만, 3D 카드 내용은 화면에 보이는 카드와 이웃에만 만듭니다. 연속 이동 중에는 현재 위치부터 목적지까지 준비해 중간 카드가 빈 채로 지나가지 않게 합니다. 매 프레임 React 상태를 갱신하지 않고, 보이는 슬라이드가 바뀔 때 렌더링 범위를 조정합니다.

[가로 카드 UI와 렌더링 최적화 가이드](docs/horizontal-card-ui-and-windowing.md)는 한 장에 집중하는 배치, 세 장을 기본으로 하는 렌더링 범위, 이동 중 예외 처리와 카드 상태 보존을 설명합니다.

카드의 가로 이동과 답변의 세로 스크롤은 중첩된 기본 스크롤 영역에서 처리합니다. 터치 이벤트를 취소하거나 화면 가장자리 제스처를 별도로 흉내 내지 않습니다. 보조 화면은 닫기 버튼과 아래로 끌어 닫기를 지원하는 모달이며, 터치 조작의 대체 버튼과 키보드 접근도 제공합니다. iPhone 안전 영역과 동작 줄이기 설정을 반영합니다.

## 검증

```powershell
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

단위 검사는 노트 변환 규칙, 샘플 덱의 평가 기준 누락과 비교 답변 구분, 질문 파일의 형식 검사와 링크 인코딩을 확인합니다. 브라우저 검사는 샘플 덱(`#sample`)으로 모바일 크기에서 탭, 스크롤, 검색, 책갈피와 재접속을 확인합니다. 질문 파일 불러오기, 저장소가 빈 다른 기기에서 링크로 열기, 잘린 링크와 지우기도 확인합니다. 슬라이드 검사는 기본 터치와 휠 입력 중 양쪽 카드의 실제 위치, 이동 중 재입력, 나가는 답변의 보존과 화면 크기가 달라진 뒤의 정렬을 확인합니다. 자동 캡처와 실행 결과는 Git에서 제외한 `.captures`와 테스트 결과 폴더에 저장합니다. Playwright의 모바일 환경과 WebKit 검증은 실제 iPhone Safari의 시스템 제스처와 주소창 동작을 완전히 재현하지 않으므로 실기기 확인도 필요합니다.
